# 抖音带货宣传与承诺评分参考库

内容库版本1.4，新增14条带货参考规则与7条官方来源记录。规则及来源保存在`backend/app/data/content_library/`。

带货练习点评时，AI接收规则适用范围、证据要求、正反例、例外条件及来源核查状态。报告单独展示“宣传与承诺核查”，可展开查看待核实资料与官方来源。

## 判断边界

当前14条规则启用内部参考，未启用确认问题或自动扣分。官方现行版本、部分专项直接依据尚未核完；来源ID存在不等于条款已核实。资料不足不等于事实虚假，观众引用和否定表述不能当成主播承诺。

平台候选条款产生的`reference_notes`独立于`issues`和`top_issue_ids`保存，不影响问题数量和前后对比。服务端校验具体规则、来源、原话及时间范围；同一片段参考项合并。旧的带货真实性规则也须提供商品资料逐字证据，缺资料时只提示核实。

## 生效与兼容

重启后端后重新加载内容库；启动时为旧`feedbacks`表增加`reference_notes`字段，迁移幂等且保留原记录。新报告采用新逻辑，旧报告不自动重新计算。仓库内前端静态构建已更新。

## 验证

后端全套172项通过后补充了迁移及知识直播边界测试，最终12项规则专项通过；前端类型检查及生产构建通过。真实模型使用自编话术抽样，成功引用具体抖音规则；最终参考门禁重放合并为2条参考、0条确认问题。此抽样不是准确率评估或平台认证。

`review_cases.jsonl`是34个项目自编的内容审核例子，不是真实用户直播语料，也不是已经运行的模型评测集。实际自动测试见`backend/tests/test_douyin_reference.py`。

## 转为确认问题依据

逐条确认完整现行官方条款、生效信息、适用范围并通过内容审核后，设置来源`current_effectiveness=verified`、规则`review_status=approved_for_scoring`以及`enabled_for_scoring=true`。服务端要求同时满足以上条件，仍需具体证据，不推断平台处罚或上播资格。本次不新增数值扣分。
