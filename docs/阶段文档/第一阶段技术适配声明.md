# 技术适配声明

> 项目：AI 主播陪练｜PRD v0.1｜日期：2026-09-18
> 本声明供产品经理审阅，只需确认三件事：①理解对不对；②有没有新增 PRD 没要求的费用/平台/范围；③被暂缓的能力会不会影响本阶段验收。

## 1. 产品形态判断
- 产品类型与核心任务：音视频驱动的 AI 陪练。个人/机构主播用摄像头和麦克风进入模拟直播间练习表达与互动，AI 生成动态弹幕，练后给出带时间点证据的反馈，并支持立即重练、前后对比进步。首版电脑网页端。
- 核心交互：多轮/准实时互动（面对镜头说、看到弹幕）+ 分阶段确认（练后反馈 → 重练 → 对比）+ 摄像头麦克风采集。
- 开发路径：**纵向切片（路径 B）**。理由：本产品的核心价值必须"用眼睛看、亲手操作"才能判断（弹幕是否随发言变化、反馈是否可跳转到具体片段、录像能否回看），且浏览器摄像头/麦克风采集是决定产品可行性的终端能力，必须在第一阶段用最小真实界面跑通端到端链路，不能只靠 JSON 或自动化测试。
- 当前阶段范围：阶段 2 的最小纵向切片 = 一条个人主播端到端链路：创建练习（选直播类型/训练目标）→ 设备检查 → 模拟直播（预设关键问题 + 动态 AI 弹幕 + 录像保存）→ 练后反馈（转写 + 带时间点问题 + 重练入口）。机构功能最小闭环与基础镜头提醒后置到本切片验证通过后再做。

## 2. 采用的默认方案
- 后端 Python 3.12 + FastAPI：与线上运行时一致，能力可测试、可调 API。
- Pydantic：校验接口请求/响应与模型结构化输出。
- pytest：mock 自动化测试，覆盖业务逻辑与错误路径。
- SQLite + SQLAlchemy + Alembic：存在训练任务、录像、转写、弹幕事件、反馈、用户/机构成员等多实体关系，需要结构化持久化与迁移。
- 录像等大文件：本地文件目录存储，不塞进数据库。
- 模型调用：官方 SDK 或验证过的兼容接口（LLM 用 DeepSeek，转写用国内 ASR）。
- 最小验收界面：单个 HTML 放后端 `static/`，原生 JS + fetch/SSE，用于本阶段端到端验收；正式前端（Next.js）阶段 3 再做。

## 3. 触发的按需模块
- SQLite + SQLAlchemy + Alembic：由多实体关系/账户/机构成员触发；当前阶段引入（MVP 单用户先建最小表结构）。
- 语音转写 ASR：由"练后反馈依赖转写"触发；当前阶段引入（**新增外部平台 + 按量费用**，见第 4、6 节）。
- SSE：由"弹幕逐步出现、转写/反馈过程可视化"触发；本切片先按"提交 + 异步分析"实现，若验收发现需要流式再引入，暂缓。
- 大文件存储：由"录像保存与回看"触发；当前阶段引入（本地目录）。
- 画面检测（镜头提醒 F12）：由"是否入镜/画面是否清楚"触发；**暂缓**，切片跑通后作为第二切片加。
- RAG / 向量库（Chroma）：未触发（机构内容检索后做）；不引入。

## 4. 偏离或暂缓的默认方案
- 正式前端 Next.js：本阶段用最小验收界面替代；原因：核心链路未验证前不铺开正式视觉；影响：阶段 3 再建正式前端；未来当切片验证通过且进入阶段 3 时启用。
- 机构功能最小闭环：暂缓到本切片验证通过后（第二切片）；原因：第一版首要验证目标是个人主播反复练习、看到进步；影响：机构用户本阶段无入口，但不影响个人主播链路验收。
- 基础镜头提醒 F12：暂缓；原因：独立图像检测能力，先跑通核心闭环；影响：本阶段无镜头提醒，属 PRD 已允许后置的 P0 细化项。
- SSE 流式输出：暂缓；原因：先按异步模式验证，避免过早引入复杂度。
- 新增外部平台（语音转写 ASR）：PRD 未点名，属新增平台与费用。推荐**国内 ASR 服务**（首选讯飞开放平台语音转写，个人可开通、按音频时长计费；若你已有阿里云/腾讯云账号，也可用其 ASR）。费用量级我待核查官方当前价后给你确认；开发阶段无 Key 时先用 mock 转写推进，验收前你再提供 Key。

## 5. 强制底线检查
- 密钥与隐私：通过。密钥只进本项目 `.env`（gitignore），不回显、不进仓库/前端；录像/转写（含人脸声音）境内处理、只发国内厂商、不用于训练；权限判断在后端。
- 数据与任务可恢复：通过。训练任务、转写、弹幕事件、反馈持久化到 SQLite，录像持久化到文件目录，进程重启可恢复，验收时实测。
- 输入输出校验：通过。Pydantic 校验接口与模型结构化输出；录像文件校验格式/真实类型/大小；年龄确认校验 18+。
- 错误与日志边界：通过。统一 `{"error": {"code","message"}}` 结构，不泄露堆栈；日志不记密钥、完整录像、完整用户发言原文。
- 测试与真实模型验收：mock 自动化测试 + 真实模型冒烟（转写、动态弹幕、练后反馈三处各跑通一次）；D2/D3 质量线在首次真实冒烟用 5–10 条真实样例由产品经理打分确定。
