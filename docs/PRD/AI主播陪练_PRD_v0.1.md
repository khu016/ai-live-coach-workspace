# AI 主播陪练｜产品需求文档（PRD）

版本：v0.1  
状态：需求对齐版，供产品、设计与开发评审  
日期：2026-09-18

## 1. 产品概述

AI 主播陪练是一款面向个人主播和直播机构的开播前训练产品。第一版为电脑网页端，主播使用摄像头和麦克风，在模拟直播间中练习表达与互动。产品提供教程、单项难点练习和完整模拟直播三个可自主选择的入口。练习结束后，系统指出有具体证据的问题，并支持主播立即重练、比较进步。

产品覆盖带货、娱乐互动、知识内容三类直播。直播类型由用户在创建训练时选择，不以某个商品品类作为产品定位。个人主播可自行训练；机构可分配训练、查看获授权的练习记录，并由带教老师决定新人是否达到上播标准。

### 1.1 目标用户

| 角色 | 主要需求 |
| --- | --- |
| 个人主播或新人主播 | 在正式开播前安全地反复练习，知道具体哪里需要改进，并看见自己的进步 |
| 机构带教老师／培训负责人 | 给新人分配训练，查看录像、反馈和成长记录，作出人工考核判断 |

### 1.2 第一版验证目标

首要验证个人主播是否愿意反复练习，以及是否能从前后两次练习中看见具体进步。机构功能保留，但机构培训效率暂不作为第一版的首要成功标准。量化目标值需要试点后确定，见第 10 节。

### 1.3 产品原则

- 教程是可选资源，不是进入练习的前置步骤。
- AI 反馈必须指向可回看的具体片段或对话，避免只给笼统分数。
- 每次优先指出最值得改进的 1–2 个问题，并提供直接重练的入口。
- 评分只作辅助。AI 不自动判定主播可否正式上播。
- 当缺少商品或主题资料时，不声称已核实相关事实。

## 2. 版本范围

### 2.1 第一版包含

1. 个人账号与机构成员身份。
2. 选择直播类型、训练目标，并可选填主题、商品资料或脚本。
3. 内置教程、AI 推荐练习、机构自有培训内容。
4. 单项难点练习与完整模拟直播。
5. 摄像头、麦克风采集及练习录像回看。
6. 固定关键训练问题与随主播发言变化的 AI 弹幕。
7. 有时间点依据的练习反馈、针对性重练、同一任务的前后片段比较。
8. 机构端练习分配、录像与成长记录查看、基本考核项调整。
9. 基础镜头提醒，如是否入镜、画面是否清楚。

### 2.2 第一版不包含

- 直播中实时辅助、真实直播平台连接或代替主播开播。
- 复杂的机构训练场景编辑器。
- 自动评价眼神、表情、手势或“感染力”。
- AI 自动作出上播资格决定。
- 将训练分数直接推断为真实直播的流量或成交提升。

## 3. 使用路径

产品首页同时展示“看教程”“练一个难点”“完整模拟直播”，用户可以从任一入口开始，也可以在练习后切换到其他入口。

```text
选择任一入口
├─ 看教程 ────────────────┐
├─ 练一个难点 ────────────┼→ 查看具体反馈 → 重练／看相关教程／换一个练习
└─ 完整模拟直播 ──────────┘
```

### 3.1 个人主播路径

1. 选择带货、娱乐互动或知识内容直播，并选择想练的能力或完整模拟。
2. 只填写必需选项即可开始；主题、商品资料和脚本均为可选输入。
3. 确认摄像头、麦克风和录像保存提示后开始练习。
4. 在模拟直播间面对预设问题和动态弹幕进行表达与互动。
5. 结束后查看录像、带时间点的反馈及最需要改进的 1–2 个问题。
6. 选择重练同一问题、看相关教程、进行完整模拟或结束本次训练。

### 3.2 机构路径

1. 培训负责人添加自有教程或资料，选择基本考核项，给成员分配练习。
2. 主播在个人练习入口或机构任务入口完成训练。
3. 有权限的带教老师查看任务录像、AI 反馈和历史变化，作出人工评价。

## 4. 功能需求

优先级说明：P0 为第一版必须完成；P1 为第一版可延后完善。下表是需求范围，具体界面与技术实现由设计和开发评审确定。

| ID | 优先级 | 功能 | 需求与规则 |
| --- | --- | --- | --- |
| F01 | P0 | 训练入口 | 首页并列提供教程、单项练习、完整模拟入口；任一入口均可直接进入，不设置强制学习顺序。 |
| F02 | P0 | 创建练习 | 用户选择直播类型与训练目标；可选填主题、商品资料或脚本。无可选资料时仍可开始。 |
| F03 | P0 | 教程 | 提供内置教程；AI 可按用户练习问题推荐相关内容。推荐不得阻断用户自主选择。 |
| F04 | P0 | 单项练习 | 支持针对开场、冷场处理、弹幕应答等目标进行短练；具体首发题目清单待试点确定。 |
| F05 | P0 | 完整模拟 | 用户连续完成一场模拟直播。练习时长和阶段设置待验证，不在本版文档中预设固定值。 |
| F06 | P0 | 模拟观众 | 每项训练保留预设的关键问题；其他弹幕根据主播发言与当前场景动态生成。界面明确标注为模拟观众。 |
| F07 | P0 | 音视频采集 | 开始前检查摄像头、麦克风及用户授权；练习中显示本机画面与弹幕；保存可回看的音视频记录。 |
| F08 | P0 | 练后反馈 | 结合转写、互动事件和基础画面检查，按表达表现、直播应对、内容质量提供反馈；关键结论关联可回看的时间点。每次突出 1–2 个优先问题。 |
| F09 | P0 | 重练与进步 | 从反馈直接进入相应单项练习；支持比较同一任务前后两次的相关片段与能力变化。分数仅为辅助信息。 |
| F10 | P0 | 录像管理 | 录像默认保存在账号中；个人练习默认仅本人可见；机构任务仅获授权的带教老师可查看；用户可查看与删除自己的记录，机构记录的删除规则待确认。 |
| F11 | P0 | 机构任务 | 机构负责人分配训练，查看成员完成情况、录像和成长记录，修改基本考核项；带教老师人工记录是否通过。 |
| F12 | P0 | 基础镜头提醒 | 对未入镜、画面明显不清楚等客观问题给出提醒；不输出主观的感染力或外貌评分。 |
| F13 | P0 | 机构内容管理 | 支持机构以文本方式加入自有教程与参考资料；文件上传格式、大小和版本管理规则待确认。 |
| F14 | P0 | 个性化训练安排 | AI 根据已出现的训练问题推荐下一项练习或教程；用户可忽略或自行选择。 |

## 5. AI 在产品中的职责与边界

| 环节 | AI 职责 | 必须遵守的边界 |
| --- | --- | --- |
| 创建练习 | 根据直播类型、目标和可选资料生成场景与模拟观众设定 | 不编造用户未提供的商品功效、价格或承诺 |
| 模拟直播 | 理解主播当前发言，生成追问、质疑和普通互动弹幕 | 必须覆盖固定训练点；动态弹幕不得脱离训练目标或伪装为真实观众 |
| 练后反馈 | 分析转写和互动记录，给出带时间点的证据、改进建议和重练入口 | 区分观察到的行为与推测；没有资料时不做具体商品事实核验 |
| 后续推荐 | 推荐相关教程或练习 | 保留主播自主选择权，不设强制课程顺序 |

基础镜头提醒可使用独立的图像检测能力实现。AI 不对眼神、表情、手势和感染力给出第一版自动评分。机构带教老师保留最终上播判断权。

## 6. 页面与权限

### 6.1 页面清单

1. 训练首页：三个自主入口、近期练习和建议。
2. 训练创建页：直播类型、目标、可选资料及设备检查。
3. 教程页：教程列表、详情与相关练习入口。
4. 模拟直播页：摄像头画面、弹幕、训练状态与结束控制。
5. 训练报告页：录像、时间点反馈、重点问题和重练入口。
6. 成长记录页：同一任务前后片段及能力变化。
7. 机构管理页：成员、任务分配、内容、考核项与查看权限。

### 6.2 权限原则

| 数据或操作 | 个人主播 | 机构负责人／带教老师 |
| --- | --- | --- |
| 个人自主练习录像 | 本人查看和删除 | 默认不可见 |
| 机构任务录像 | 练习主播查看 | 获授权后查看 |
| 分配机构训练与调整考核项 | 不可操作 | 按机构角色操作 |
| 上播通过判断 | 查看结果 | 带教老师人工决定 |

账号归属、主播退出机构后的录像权限和机构任务录像的删除规则属于待确认事项；在规则确定前不能用权限含糊的默认共享实现。

## 7. 异常与降级

- 摄像头或麦克风未授权、设备不可用：阻止开始音视频练习，说明原因并提供重新检查入口。
- 网络中断：明确提示录制和互动是否仍在进行，避免用户误以为完整保存；恢复后是否续接或重新开始由技术方案确定。
- 动态弹幕生成超时：使用与当前训练点相关的预设弹幕继续练习，并在后台记录故障。
- 转写或反馈失败：保留已成功保存的录像，提示稍后重试分析；不展示未经证实的评分。
- 画面检测信心不足：不输出判断，允许用户自行回看。
- 用户资料与 AI 生成内容冲突：以用户已确认的资料为依据；无法确认时标明未知。

## 8. 验收标准

1. 新用户不看教程，也能选择单项练习或完整模拟并完成一次训练。
2. 提供或不提供主题／商品／脚本资料，都能成功创建适用的练习。
3. 一场练习能出现预设关键问题，且动态弹幕会随主播不同发言发生相关变化；失败时有可用的预设弹幕降级。
4. 练习报告中的重点反馈可跳转至对应录像片段，并可直接发起重练。
5. 同一训练任务的两次练习可对比具体片段；用户能看见能力变化，而不必依靠总分理解进步。
6. 个人自主练习录像不会出现在机构查看列表；机构任务仅对获授权角色可见。
7. AI 不自动显示“可上播”结论；机构通过状态来自带教老师的人工操作。
8. 未提供商品事实资料时，系统不输出“已核实商品信息”之类的结论。
9. 摄像头和麦克风权限被拒绝时，界面给出可操作的处理提示，不进入假装正在录制的状态。

以上是功能验收条件。实时互动延迟、转写准确率、反馈一致性等数值门槛需在技术验证与试点中确定，不能在未测试前填写承诺值。

## 9. 数据与隐私要求

- 首次使用摄像头和麦克风前，明确说明录制用途、默认保存、可见范围及删除入口。
- 个人自主练习与机构任务分别管理权限，后台接口也必须按身份校验。
- 保存录像、转写、弹幕事件、反馈与重练记录，以支持时间点回看和进步对比。
- 机构上传的培训资料只用于其授权范围内的训练，不默认进入其他机构或个人的内容库。
- 留存期限、退出机构后的数据归属、未成年人使用和适用法规要求需在上线前单独确认。

## 10. 试点与待决策项

### 10.1 建议观察的指标

| 指标 | 用途 | 目标值 |
| --- | --- | --- |
| 首次练习完成率 | 判断创建、设备检查和模拟流程是否顺畅 | 待试点确定 |
| 一段时间内的再次练习率 | 验证个人主播是否愿意反复练 | 观察周期与目标值待定 |
| 同一训练点前后表现变化 | 判断重练是否带来可见进步 | 评价方法与目标值待定 |
| 反馈有用性评价 | 验证 AI 建议是否具体可信 | 量表与目标值待定 |
| 带教老师对反馈的一致性评价 | 检查机构场景中的评估可信度 | 试点后确定 |

### 10.2 待确认问题

1. 首批试点用户来自个人主播、直播机构，还是两者都有；各自人数与招募方式。
2. 单项练习和完整模拟的默认时长、训练题库以及难度设置。
3. 机构任务录像的保留、删除与主播离开机构后的访问规则。
4. 机构自有内容的首批支持格式，以及是否需要人工审核。
5. 支持的浏览器、设备最低要求、并发与成本约束。
6. 定价、付费模式和获客渠道。
7. 主播训练效果的量化标准以及人工评审样本来源。

## 11. 文档范围说明

本文件描述第一版产品需求，尚不指定模型供应商、具体架构、数据库或部署方式。架构方案应在本 PRD 评审后另行形成。用户原始需求中未确定的事实均保留为待确认项，不以假设冒充结论。
