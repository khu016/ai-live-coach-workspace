# 第一阶段技术开发文档｜个人主播最小纵向切片

> 配套文档：`docs/PRD/AI主播陪练_PRD_v0.1.md`、《AI Agent 产品 Vibe Coding 通用技术栈手册》、《第一阶段技术适配声明》。
> 本文档只覆盖阶段 2 的第一阶段（个人主播最小纵向切片）。AI 开发时不得提前实现机构功能、镜头提醒、正式前端等其他阶段能力。

## 一、阶段目标
- 交付范围（对齐 PRD 第 8 节个人主播相关验收）：一条个人主播端到端链路——创建练习 → 设备检查 → 模拟直播（预设关键问题 + 主题相关弹幕池 + 录像）→ 练后反馈（转写 + 带时间点证据的问题 + 重练入口）→ 重练并对比前后。
- 阶段产物：FastAPI 后端 + 最小验收界面（单个 HTML，浏览器摄像头麦克风采集、弹幕、录像回看、反馈与重练）+ mock 自动化测试 + 真实模型冒烟记录。
- 验收标准（对齐 PRD 8 的 1/2/3/4/5/8/9 条）：
  1. 新用户不看教程，也能选直播类型/目标并完成一次训练；
  2. 填或不填主题/商品/脚本，都能成功创建练习；
  3. 一场练习出现预设关键问题，弹幕有主题相关变化，失败时有预设弹幕降级（"随发言实时变化"见第六、十二节待验证）；
  4. 反馈可跳转到对应录像片段，并可发起重练；
  5. 同一任务两次练习可对比片段；
  8. 未提供商品资料时，不输出"已核实商品信息"类结论；
  9. 摄像头/麦克风被拒绝时给可操作提示，不进入假装录制状态。
- 明确不做（本切片范围外）：机构功能（F11/F13）、基础镜头提醒（F12）、教程与 AI 推荐（F03/F14）、邮箱验证码登录（先单用户本机验证，登录后置）、正式前端 Next.js、商品/主题文件导入（仅文本）。
- 本阶段打通的主链路片段：`创建练习 → 弹幕脚本下发 → 浏览器录制 → 提交录像与弹幕事件 → 异步转写 → 异步生成反馈 → 反馈页(跳片段/重练) → 重练建新任务 → 前后对比`。

## 二、技术适配摘要
- 引用《技术适配声明》结论：音视频陪练产品，开发路径为纵向切片；本切片先个人主播闭环。
- 本阶段采用默认方案：Python 3.12 + FastAPI + Pydantic + pytest；SQLite + SQLAlchemy + Alembic；录像本地文件目录；LLM DeepSeek；最小验收界面（static HTML）。
- 本阶段启用按需模块：SQLite/SQLAlchemy/Alembic（多实体关系）、语音转写 ASR（反馈依赖，先 mock 后接讯飞）、大文件本地存储（录像）。
- 本阶段偏离/暂缓：SSE（先"提交+轮询"）；机构功能、镜头提醒、正式前端（后置）。
- 开发路径：纵向切片。

## 三、技术栈与模型
- 组件：Python 3.12（uv 管理）、FastAPI、Pydantic v2、SQLAlchemy 2、Alembic、pytest、python-multipart（录像上传）、httpx（模型 SDK 调用）。
- 不引入：Chroma/RAG（无检索需求）、python-docx/pypdf（无文档需求）、Redis/任务队列（单进程即可）。
- 模型：LLM 用 DeepSeek `deepseek-chat`，base_url `https://api.deepseek.com/v1`，通过配置读取、不硬编码；转写 ASR 先 `MockProvider`（开发/测试），真实接入讯飞开放平台语音转写（Key 验收前提供）。
- 模型配置项：`MODEL_PROVIDER`、`MODEL_NAME`、`MODEL_API_KEY`、`MODEL_BASE_URL`、`ASR_PROVIDER`、`ASR_API_KEY`（均走 `.env`）。

## 四、环境与配置
- `.env.example`（不含秘密）：
  ```
  MODEL_PROVIDER=deepseek
  MODEL_NAME=deepseek-chat
  MODEL_API_KEY=
  MODEL_BASE_URL=https://api.deepseek.com/v1
  ASR_PROVIDER=mock        # mock | xfyun
  ASR_API_KEY=
  DATA_DIR=data
  RECORDING_MAX_MB=1024
  PRACTICE_MAX_SEC=1200
  ```
- 需要用户提供：DeepSeek API Key（开发期可不提供，先 mock；验收前提供）；讯飞 ASR Key（同上，验收前提供）。
- 启动：`PYTHONPATH=backend uv run uvicorn app.main:app --host 127.0.0.1 --port 8000`；端口 8000 冲突时改用 8001 并记录。
- 依赖服务：无（本机 SQLite + 本地文件目录）。

## 六、数据、资产与状态
- 持久化：SQLite（多实体关系）+ 本地 `data/recordings/` 存录像文件；录像元数据入库，大文件不入库。
- 数据表（本切片）：
  - `trainings`：id、user_id（单用户默认 1）、live_type（枚举）、goal、topic、product_info、script、status、prev_training_id、created_at、finished_at。
  - `recordings`：id、training_id、file_path、duration_sec、size_bytes、created_at。
  - `transcripts`：id、training_id、segments(JSON：[{start,end,text}])、full_text、created_at。
  - `bullet_events`：id、training_id、kind（fixed_question/dynamic/fallback）、text、at_sec、source、created_at。
  - `feedbacks`：id、training_id、issues(JSON)、top_issue_ids(JSON)、created_at。
- 资产规则：录像校验真实类型/扩展名、大小 ≤1GB、时长 ≤20 分钟；文件名用训练 ID + 随机后缀，防路径遍历；不自动删除（删除规则见 D6，本切片不提供删除入口，后续切片做）。
- 状态机（trainings.status）：`created → recording → saved → transcribing → analyzing → feedback_ready`，任一步可 `failed`（转写/分析失败可重试）；状态持久化，重启可恢复；异步步骤"提交后轮询"，不用内存变量。

## 七、API / 工具设计
统一错误：`{"error":{"code","message"}}`；无 SSE，长任务用"提交 + 轮询"。

| 方法 | 路径 | 请求 | 响应 | 校验 |
| --- | --- | --- | --- | --- |
| POST | /api/v1/trainings | {live_type, goal, topic?, product_info?, script?} | {training, script:[{at_sec,kind,text}]} | live_type 枚举；goal ≤200 字；可选输入 ≤1000 字；未填资料仍可创建 |
| GET | /api/v1/trainings/{id} | - | {training} | id 存在性 |
| POST | /api/v1/trainings/{id}/finish | multipart: 录像 + bullets[{at_sec,kind,text}] | {training(status)} | 录像格式/大小/时长；bullets 非空；触发异步转写→分析 |
| GET | /api/v1/trainings/{id}/feedback | - | {status, feedback?} | 轮询直到 feedback_ready/failed |
| GET | /api/v1/trainings/{id}/recording | - | 录像文件流 | id 存在、录像已保存 |
| POST | /api/v1/trainings/{id}/retrain | - | {training(新，prev_training_id=原)} | 仅 feedback_ready 可重练 |
| GET | /api/v1/trainings/{id}/compare | - | {current, previous, clips} | 存在 previous 才可对比 |

弹幕脚本：POST /trainings 时后端返回 `script` 数组——固定关键问题（内置题库，每直播类型 3–5 条占位）+ 主题相关弹幕池（有 topic 时用 LLM 预生成，无 topic 用通用互动弹幕模板）。本切片弹幕不依赖实时理解发言；"随发言实时变化"依赖流式 ASR，后置（第十二节）。

## 八、Prompt 设计
Prompt 独立文件（`services/prompts/`），角色/输入/输出/约束如下：

1. `feedback.md`（练后反馈，核心）：
   - 角色：直播陪练教练，只评表现、不作上播资格结论。
   - 输入：live_type、goal、topic/product_info（可空）、转写 segments（含时间戳）、bullet_events。
   - 输出：JSON `{issues:[{dimension,start_sec,end_sec,evidence,problem,suggestion,retrain_target}], top_issue_ids:[1-2]}`。
   - 约束：dimension 仅限"表达表现/直播应对/内容质量"三档；evidence 必须逐字引用转写原文；每次只突出 1–2 个优先问题；无商品资料时不得声称"已核实商品信息"；不评价眼神/表情/手势/感染力。
   - 格式三件套：给正例 + 反例（禁止用 `1.1` 编号代替字段）；解析器宽容兼容多种等价格式；数量超标记质量瑕疵、不反复重试烧钱。
2. `bullets.md`（主题相关弹幕池，可选）：输入 live_type/goal/topic，输出弹幕短句列表（每条一句）；无 topic 时走通用模板兜底。

解析与存储：模型输出 → 确定性解析 → Pydantic 强校验 → 失败有限重试（≤2）→ 仍失败统一错误；evidence 的时间戳回落到转写 segments 校验。

## 九、验收界面或纵向切片
- 需要最小界面（本产品必须"用眼睛看、亲手操作"才能判断质量），是纵向切片的第一条真实切片，不是一次性丢弃工具。
- 功能上限：创建练习表单、设备检查（getUserMedia，拒绝时提示）、模拟直播页（本机画面 + 弹幕按时间轴出现 + 结束按钮）、反馈页（录像回看 + 时间点问题 + 重练）、对比页。
- 目标终端：电脑网页端 Chrome/Edge 近两年版本；不要求移动端（阶段 3 正式前端再适配）。
- 技术：单个 `static/index.html`，原生 JS + `fetch`；MediaRecorder 采集并上传。

## 十、测试要求
- 第一层 mock 测试（pytest，模型调用全 mock）：
  1. 创建练习：live_type 非法、goal 超长、缺 goal 报错；无 topic 也可创建；
  2. 弹幕脚本：有/无 topic 都返回非空 script，含 fixed_question；降级路径覆盖；
  3. 状态机：created→recording→saved→transcribing→analyzing→feedback_ready 合法流转；非法跳转报错；failed 可重试；
  4. 反馈解析器（纯函数重点）：正例、`1.1` 编号反例、多给 issue、缺字段、非法 JSON 的宽容解析与强校验；数量超标不重试；
  5. 录像校验：伪造扩展名、超大、超时长、空文件报错；
  6. 重练/对比：非 feedback_ready 不可重练；无 previous 不可对比；prev_training_id 关联正确；
  7. 错误路径：统一 error 结构；异步步骤 mock 转写/分析失败→failed；
  8. 重启恢复：进程内新建连接后状态仍从库读回。
- 第二层真实冒烟（验收前必做，无 Key 如实写"待验"）：用真实 DeepSeek 跑通一条完整"真实转写文本 → 反馈 → 持久化 → 反馈页可见"；记录模型、耗时、Token/成本；ASR 有 Key 后跑真实转写并记录。格式合规率区分"首测合规/重试后合规"，数量遵守率单独记录。
- 数据恢复、错误路径、文件安全见上；关键交互在浏览器实测。

## 十一、验收清单（产品经理照做）
- [ ] 打开 http://127.0.0.1:8000/ ，选"带货/娱乐互动/知识内容"任一类、填一个训练目标，不填主题/商品也能点"开始"。
- [ ] 弹窗询问摄像头麦克风时点"拒绝"，页面给出可操作提示（不是进入假装录制）。
- [ ] 重新授权后进入模拟直播页：能看到自己画面；弹幕按时间出现，且能看到预设的"关键问题"。

- [ ] 点"重练"，完成第二次练习后，能看到前后两次的对比片段。
- [ ] 全程未填商品资料时，反馈里不出现"已核实商品信息"类说法。
- [ ] 未接真实 Key 时，页面明确标注当前为模拟/待验，不伪装成真实效果。

## 十二、风险与待确认项
- 已知限制（本切片）：弹幕"随主播发言实时变化"依赖流式 ASR，本切片降级为"预设关键问题 + 主题相关弹幕池"，属待验证项，不冒充已实现。
- 成本：LLM 单场 ≤1 元、开发期每月 ≤100 元（D4 占位）；ASR 按音频时长计费，接前核查讯飞官方当前费率并告知量级。
- 安全/隐私：录像/转写境内处理、只发国内厂商、不用于训练（D7）；单用户本切片无权限越权面，登录与"仅本人可见"在后续切片实现。
- 迁移风险：SQLite → 生产 PostgreSQL、本地录像目录 → 对象存储，留待阶段 4 输出迁移方案。
- 待产品经理决定：无（本阶段无需新决定）。D2/D3 留待首次真实冒烟打分；D9 阶段 4 前确认。
